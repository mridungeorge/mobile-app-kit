# Habit Tracker — Native Android Starter (Kotlin + Jetpack Compose)

A production-shaped Android Studio/Gradle project generated by **Mobile App Factory**.
It builds and runs with no API key and no backend: the fake API client returns a few rows and
Room keeps them, so every screen has real data on first launch.

- Language: Kotlin (compiled by AGP 9's built-in Kotlin — there is no `kotlin-android` plugin)
- UI: Jetpack Compose + Material 3
- Build: Gradle 9.9.1, AGP 9.5.1, Kotlin DSL, version catalog
- `compileSdk` / `targetSdk`: 37 (re-verify Play requirements at submission)
- `minSdk`: 26
- DI: Hilt · Storage: Room + DataStore · State: one `UiState` per screen

## Run it

```bash
# Gradle wrapper is included; a JDK 17 is all you need.
./gradlew :app:assembleDebug
./gradlew :app:installDebug
```

On Windows, put the SDK path in `local.properties` with the drive colon escaped:
`sdk.dir=C\:/Users/you/AppData/Local/Android/Sdk`. Without it, set `ANDROID_HOME`.

Or open this folder in **Android Studio** and press Run.

> Version numbers in `gradle/libs.versions.toml` are starter values. The Kotlin pin exists only
> for the Compose compiler plugin — it must match the Kotlin AGP embeds, and KSP must be a
> version that understands built-in Kotlin. Check both before bumping either.

## Where things live

```

app/src/main/java/com\example\habittracker/MainActivity.kt                  edge-to-edge Compose host
app/src/main/java/com\example\habittracker/di/AppModule.kt                  DI graph (swap fake -> live API here)
app/src/main/java/com\example\habittracker/data/api/ApiClient.kt            API boundary + FakeApiClient
app/src/main/java/com\example\habittracker/data/db/                         Room entity, DAO, database
app/src/main/java/com\example\habittracker/data/settings/                   DataStore preferences
app/src/main/java/com\example\habittracker/data/auth/AuthRepository.kt      email + Apple/Google stubs
app/src/main/java/com\example\habittracker/feature/                          one ViewModel per screen
app/src/main/java/com\example\habittracker/ui/App.kt                        NavHost, bottom bar / rail
app/src/main/java/com\example\habittracker/ui/UiState.kt                    loading/empty/offline/error/content
app/src/main/java/com\example\habittracker/ui/screens/                      home, detail, settings, auth, deletion
app/src/main/res/xml/locales_config.xml                             per-app language list
```

Design tokens come from the skill and are pre-mapped in `ui/theme/Color.kt`, `ui/theme/Type.kt`
and `ui/theme/Motion.kt`. Keep to the Rune rules: neutral surfaces, one accent, hairline borders
instead of large shadows, 4/8/12/16/24 spacing, and motion that stops when the system animator
setting is off.

```bash
./gradlew :app:connectedDebugAndroidTest  # runs the DAO test on a device/emulator
```

## Release checklist (short)

1. Create an upload keystore and `keystore.properties`, then add the signing config to `app/build.gradle.kts`.
2. Enable Play App Signing in Play Console.
3. Set `versionCode` / `versionName` for every upload.
4. Replace the `https://example.com/account/delete` web-deletion URL and the placeholder auth
   providers — Apple and Google sign-in fail loudly until you wire the real SDKs.
5. Run `./gradlew :app:lintDebug :app:testDebugUnitTest :app:bundleRelease` and fix every lint error.
6. Complete the Play data-safety form to match the SDKs actually shipped.
7. Start the closed test track early — new personal accounts need **12 testers for 14 continuous
   days** before production access.

Full guidance: the native Android release checklist in this project's `docs/` folder.
