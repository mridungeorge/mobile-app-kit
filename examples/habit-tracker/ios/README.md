# Habit Tracker — Native iOS Starter (Swift + SwiftUI)

A production-shaped SwiftUI project generated by **Mobile App Factory**. It builds and runs with
no API key and no backend: the mock API client returns a few rows and SwiftData keeps them, so
every screen has real data on first launch.

- Language: Swift 5.9+ (strict concurrency friendly)
- UI: SwiftUI — `TabView` in compact width, `NavigationSplitView` in regular width
- Project: [XcodeGen](https://github.com/yonaskolb/XcodeGen) `project.yml` (no fragile `.pbxproj` checked in)
- Deployment target: iOS 17 (raise only if you drop older devices deliberately)
- Bundle id: `com.example.habittracker`
- Storage: SwiftData · Settings: `UserDefaults` · Strings: String Catalog (en + de)

## Run it (macOS)

```bash
brew install xcodegen
xcodegen generate
open HabitTracker.xcodeproj
```

Select a simulator and press Run. Open the project in **Xcode** for signing,
capabilities, Archive, and TestFlight.

> No Mac? You can still author the Swift sources and keep the pipeline artifacts;
> building, testing and submitting requires Xcode on macOS or a macOS CI runner. This
> kit's CI builds and runs `xcodebuild test` on a simulator, which is where these sources
> are first compiled — the authoring machine is Windows.

## Where things live

```
Sources/App.swift                                  @main, SwiftData container, environment
Sources/AppEnvironment.swift                       dependency container (swap mock -> live API here)
Sources/AppShell.swift                             tab bar or split view, per size class
Sources/Data/APIClient.swift                       APIClient protocol + Mock + Live(URLSession)
Sources/Data/Habit.swift                           @Model + repository (cache-first)
Sources/Data/SettingsStore.swift                   persisted settings
Sources/Data/AuthService.swift                     email + Apple/Google stubs
Sources/UI/UiState.swift                           loading/empty/offline/error/content
Sources/UI/StateView.swift                         renders that state for every screen
Sources/Features/                                  home, detail, settings, auth, account deletion
Sources/DesignSystem/Theme.swift, Motion.swift     Rune tokens -> SwiftUI, reduced-motion aware
Resources/Localizable.xcstrings                    translated strings
Resources/PrivacyInfo.xcprivacy                    privacy manifest starter (edit to match SDKs)
Tests/                                             UiState, repository and auth tests
```

Design tokens come from the skill and are pre-mapped in `Theme.swift`. Keep to the Rune rules:
neutral surfaces, one accent, hairline borders instead of large shadows, 4/8/12/16/24 spacing.

## Tests

```bash
# Simulator names change with every Xcode release; ask the machine for one.
SIM=$(xcrun simctl list devices available | grep -m1 -o 'iPhone [^(]*' | xargs)
xcodebuild -project HabitTracker.xcodeproj -scheme HabitTracker \
  -destination "platform=iOS Simulator,name=$SIM" CODE_SIGNING_ALLOWED=NO test
```

The suite covers the shared state machine, the cache-first repository (including offline) and
the auth providers — including an assertion that the Apple stub fails instead of faking a login.

## Release checklist (short)

1. Set your Team, bundle id, and capabilities in Xcode.
2. Add a real 1024×1024 app icon and accent colour.
3. Complete `PrivacyInfo.xcprivacy` to match the SDKs actually linked.
4. Add purpose strings for every permission you request.
5. Replace `https://example.com/account/delete` and wire the real Apple/Google sign-in flows —
   both providers fail loudly until you do.
6. Archive → upload to App Store Connect → TestFlight.
7. Fill in App Privacy, age rating (5-tier), DSA trader status (EU), and review notes.

Full guidance: the native iOS release and App Store guides in this project's `docs/` folder.
